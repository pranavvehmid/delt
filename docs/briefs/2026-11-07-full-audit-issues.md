# Brief: full technical audit, 100+ GitHub issues

- Goal: brutally audit how the whole project works, start to finish, and file at least 100 real issues on GitHub. No fixes.
- Context: src/ (app, api, lib), supabase/, .github/workflows/, android/, public/, tests, e2e, docs.
- Requirements: each issue names the location, the defect, why it matters and a suggested direction; severity + area labels; no padding or duplicates.
- Non-goals: fixing; F1 redesign (tracked separately).
- Acceptance: >= 100 open issues, linked from docs/AUDIT.md, summarised by area and severity.
- Assumptions: "brutal" = real defects and risks stated plainly at every severity.
